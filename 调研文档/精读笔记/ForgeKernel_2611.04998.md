# ForgeKernel（arXiv 2611.04998）精读笔记

> 一句话总结：架构与编码分离、封存 kernel 作新参考、跨运行复用探针验证的硬件机制知识，实现持续自演化超越专家。

## 1. 解决什么问题

LLM kernel agent 已常能超越人类专家，其定位与设计需重新思考。现有系统有两个结构性局限：①**缺乏跨运行知识积累**——每次运行从相同初始知识出发、只留本次最优 kernel，发现随运行丢弃；②**架构演化受限**——工作划分/数据流/流水线常在早期固定，后续只能在固定架构内局部调参。新算子与模型结构不断涌现，两局限直接制约持续优化。

## 2. 创新点

1. **以架构决策为中心**：架构设计与代码实现分离（arch/coding 双 agent），以显式架构决策+里程碑计划指导实现并按反馈修订，遇结构性瓶颈重审工作划分/数据流/流水线而非局部调参；区别于 GEAK/STARK/Astra 等单次运行内代码迭代系统与 Kevin/CUDA-L1 等 RL 发码方法。
2. **测量验证的跨运行知识库**：优化中发现的硬件机制须经目标 GPU 独立探针验证才入库，跨算子/跨形状共享并在决策中引用；区别于 KernelClaw/KLineage 保留专家侧知识。
3. **封存（sealing）式自演化**：通过正确性与性能验证的 kernel 封存为下一轮黑盒参考，无需新专家实现即可持续再演化架构。
4. **系统实证**：NVIDIA 1.10× 几何平均、昇腾 level-4 +25.1%，四个公开榜单第一（论文未直接对比 KernelBench）。

## 3. 方法实现

**双 agent 与封存参考（硬件行为→机制知识，而非模仿源码）**：arch agent 输入算子定义、配置、目标硬件与参考证据——对参考做 NCU/timeline 探针与 SASS 反汇编（可运行、计时、剖析但源码不可见，即 sealed），将其验证过的架构决策蒸馏为"硬件机制知识"；coding agent 只拿设计需求、接口契约与验收条件，看不到参考源码；正向传里程碑计划，反向回传轨迹与测量证据。

**架构决策与里程碑**：决策覆盖计算组织、数据流、调度与硬件映射：kernel 分解、数据依赖、tiling、线程角色、寄存器与共享内存预算；每条须写明选择、证据与预期效果，并区分观测与假设。计划为 M0…Mk：M0 落地关键结构、只验正确性与架构约束（不设性能阈值），后续里程碑结构内细调；须一起生效的决策并为一个单元，依赖定序。

**验收流程**：harness 按算子来源的官方容差查正确性（GDN/KDA 加 scaled tolerance+cosine），拒绝直接调用参考的候选；候选与参考同作业配对计时（冷 L2 平均 device 时间，S=T_ref/T_cand），增益须超噪声阈值；**机制验证**检查执行/资源特征是否如期变化。通过进下一里程碑，否则继续修改；停滞则回传证据。

**双环自演化**：运行内——可执行决策耗尽仍未达标时，arch agent 结合轨迹、测量与补充探针重订架构与计划，结构性改动从最早受影响决策（含 M0）重启，无改进则回滚。跨运行（sealing）——通过验收的 kernel 封存为下轮参考，作为黑盒参与（源码对该轮不可见），arch agent 重新测量分析、默认 +5% 为新目标而非继承源码；迭代在下一代增益不超噪声阈值或预算耗尽时终止。

**知识库与跨运行复用**：条目按硬件架构组织，记录机制、适用条件、触发症状、最小示例、已知局限；候选机制须过独立探针验证+测量证据才入库。arch agent 按任务特征与适用条件检索、在里程碑中显式引用；条目创建与使用均被记录以溯源，支持跨运行、跨算子双向回流。

## 4. 实验与结果

**设置**：27 个算子、29 个输入配置；H100 80GB（132 SMs）与 B200（148 SMs），覆盖 attention、GEMM、卷积、GDN、DSA；昇腾 910C。参考含 FlashAttention-4、DeepGEMM、cuBLAS、cuDNN、FlashInfer、FlashMLA 等专家库及 K-Search/KDA/CAKE 发布产物；arch/coding agent 分别用 Claude Fable 5.1 / Claude Opus 5。计时为冷 L2 平均 device 时间（昇腾用 CANN-Bench 托管 harness）。

**NVIDIA**：29 个配置中 25 个追平或超过参考，几何平均 1.10×（+10%）。对专家库 22 个配置：18 个追平或超过、3 个差距 <1%，几何平均 +1.6%（最高 Conv3D fwd +7.6%）；对生成系统发布全部 7 个 kernel 均超越，几何平均 +39.4%（MLA decode +170.6%、MLA prefill +146.1%、GQA decode +24.5%、TriMul +8.7%、DSA sparse attn paged +7.0%、GDN varlen +5.8%、KDA recurrent +0.4%）。

**昇腾 910C**：CANN-Bench Season 1 决赛榜全部 8 个 level-4 算子公共 case 集（每算子 20 例）上超过每算子公开最优，几何平均 +25.1%（GQA +41.8%、GRU +44.8%、GMM-SwiGLU-Quant +32.2%、SparseFA +28.5%、MHA +26.2%、MLA +12.4%、MLA-Prolog +10.1%、LSTM +9.8%）。A3 历史榜覆盖全部 53 个 L1–L4 算子：标准集 1060/1060、隐藏集 4185/4240，总分 8566.1110 第一；几何平均加速 1.759×/1.854×，合并 1.835×（权重 0.2/0.8）。SOL-ExecBench FlashInfer-Bench（B200）：26/26 kernel、660 workload，SOL Score 0.815204、Fast1 647/660（98.03%）、平均加速 5.54×，第一；截至 2026-10-30，CANN-Bench 2.0 三榜（910C/950DT/950PR）均第一。

**自演化**：专家参考路径——GQA fwd(16:1) 初始 +0.3%→+9.9%→+4.2%，累计约 +15%；DSA sparse attn fwd −0.5%→+7.2%（原架构内仅 +4.5% 即停滞，探针定位输出 store 缺重叠后改持久循环达标）；GDN prefill bwd +1.1%→+2.0%。参考自由路径（/goal 生成后再优化）——GDN prefill fwd +82.6%→再 +9.5%（累计约 +100%）；GQA fwd +22.8%→再 +5.0%（约 +29%）。DeepSeek-V4.1 融合稀疏注意力 prefill（单 agent、每代约 24h、B200，FlashMLA 仅评测用）+5.3%→+10.0%→最终 +15.5%。较通用编码 agent（/goal 设定、24h 预算）最高 +9.5%。

**消融**（对专家参考的几何平均增益）：完整系统 +0.4%；仅初始计划 −2.3%；去知识库 −3.8%（GDN prefill fwd 由 −1.5% 掉至 −16.4%）；去 SASS 反汇编 −0.3%；去里程碑模板 −0.4%（GDN prefill fwd −16.2%；attn bwd 反升但牺牲内部精度）。知识复用：SM90 cohort 几乎全部配置采用外部知识，最常见 6–10 条（约 43.5%）、最高 26–30 条，并有跨算子双向回流（DSA↔GQA、GEMM↔MHA）。

## 5. 局限与启发

**论文自述局限**：①架构探索受 agent 候选生成能力限制、可能陷入局部最优，未来需拓宽搜索空间与多样性；②知识库绑定硬件架构与适用条件，跨硬件复用需适配验证。

**启发**：①架构—编码分离+里程碑契约+机制验证把 LLM 拉回结构层思考，可迁移到其他代码任务；②封存黑盒参考是不抄源码又持续自设更高基线的自演化范式：先追平专家、再超越自己；③探针验证才入库与跨算子复用表明：硬件行为规律比算子技巧更值得作为知识单元积累。
