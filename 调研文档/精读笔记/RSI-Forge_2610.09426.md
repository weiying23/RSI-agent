# RSI-Forge（arXiv 2610.09426）精读笔记

> 一句话总结：用多智能体流水线把发表论文自动转化为带独立复现基线与自动评估器的可执行自改进研究环境。

## 1. 解决什么问题

递归自我改进（RSI）需要环境提供有挑战的问题和可靠反馈，但构造研究环境依赖领域专家：现有基准复用仓库/竞赛测试（SWE-bench、MLE-bench）或靠专家手写任务与 rubric（PaperBench、RE-Bench），规模与学科覆盖受限。研究任务环境尤其难：问题要有意义、留出改进空间，评分要自动且能区分真实增益、噪声与捷径。核心问题：**如何大规模自动构建 RSI 环境**。

## 2. 创新点

1. **首个"论文→RSI 环境"自动构建流水线**：以发表论文为原料（自带问题、方法与实测结果），区别于仓库/竞赛类基准及 Absolute Zero、SPADE 等边学边生成任务的方法。
2. **三角色信息隔离**：author/reproducer/reviewer 可见信息互不相同（作者不看下游结果；复现者不见作者实现；评审者不见求解得分），使复现与评审独立于构建。
3. **独立复现基线**：论文方法由 reproducer 以与 solver 相同的接口和预算独立重实现并测分，**复现须胜过起始解**才验收，直接证明任务有改进空间。
4. **跨领域语料库**：210 个环境、18 个领域，90 个由人类领域博士按统一 9 维 rubric 独立评审。
5. **以"连续尝试仍能改进"验证环境**：4 模型 × 3 次继承式尝试验证"环境支持 RSI"，并附轨迹行为编码。

## 3. 方法实现

**环境格式**。每环境定义研究目标、解接口与算力预算，提供可运行起始解、数据生成代码、确定性评估器、开发集与仅用于评分的 held-out 测试集。源论文、作者实现与测试数据不公开给 solver。环境另设 target score（可基于性能界或特权信息解，不必可达），按 b(v)=(v−w)/(u−w) 归一化：起始解为 0、target 为 1，复现基线为参照点。

**构建流程**（主运行三角色均用 Claude Opus 5，独立会话）：
- **Author agent**：把论文问题改编为可执行任务，写起始解、数据生成、评估器与 dev/test 划分（测试集须沿文档化任务条件区分，非随机划分），并初步实现论文方法、测量起始解与 target 分数。
- **自动检查 + Reviewer agent**（独立上下文）：审查任务可从材料理解、评估器测量预期目标；脚本测试验证性能差异超过重复评估的变异。
- **Reproducer agent**：仅凭论文与 solver 可见材料独立重实现论文方法，在测试集上建立复现基线，必须优于起始解。
- **终审**：reviewer 审复现报告 + 端到端测试（启动/提交/评分）；任一环节失败退回 author 修理（每阶段至多 3 次），仍败则拒。

**评分与防作弊**：自动检查提交的结构、接口与资源限制；独立 model judge 审查违规，违规零分。防 reward hacking：测试数据先载入内存并删除磁盘副本，求解期不返回 held-out 分数；部分环境仍遗留可访问材料（见 §4）。**筛选六条**：定量目标有改进方向、有实测基线、指标可确定性计算、适配算力、有可测改进空间、许可允许再分发；源论文均为 2026 年预印本。

## 4. 实验与结果

**构建漏斗**：10,800 篇预印本 → 2,117 合格（约 20%）→ 213 开工 → 199 过设计 → 198 过构建 → 189 过独立复现 → 180 入库；再用 GPT-5.6-sol 追加 30 个，共 **210 环境、18 领域**（每领域 6–14 个）。79% 的入库环境经修理；常见缺陷（占修理段落比）：检查检不出预期失败 66%、指令错误 63%、检查了错误代码副本 54%、不做事也得分 37%。每环境中位耗 170M tokens（99.6% 输入为缓存读）。

**质量评审**：三个 agent judge 评全部 180 个，90 个另有人类专家评审。9 维均分：专家 4.24、panel 4.54。专家给"起始解之上空间"（4.81）与"分数区分度"（4.74）最高，最苛刻于"抗饱和"（3.09 vs panel 3.98）、"对论文忠实"（3.72）与"抗捷径"（4.09）。与手工的 RSI-Exam 对比：区分度 4.65 vs 2.64、抗捷径 4.67 vs 3.92 更高，抗饱和 3.98 vs 4.41 较低。

**求解实验**：随机抽 120 个环境 × 4 模型（Opus 5、GPT-5.6-sol、DeepSeek-V4-Flash、Haiku 4.5，统一 Claude Code harness）× 3 个 60 分钟 session（新上下文但继承提交解、保存版本、日志与笔记；权重固定），共 480 条链。三次 session 中位归一化分：Opus 0.754→0.791→**0.800**（rank 1.67）、GPT 0.673→0.747→**0.761**、DeepSeek 0.550→0.594→**0.647**、Haiku 0.129→0.277→**0.332**。**84% 的环境中至少一模型在首次尝试后继续改进；120 个中 68 个被超越复现基线**（单模型计数：GPT 65、Opus 63、DS 54、Haiku 24）。超基线 session 中 **95% 含调优之外的工作**（如以平滑替代不可微容差、对单点估计参数积分），仅 5% 纯调优。

**行为与敏感性**：转录编码显示 Opus 的 exploration 占 98%、shortcuts 46%，Haiku 为 49%/82%（固定 codebook 复检 κ=0.73）。139 个可恢复日志的 session 中，接受小于报告标准误的增益：Haiku 73%、Opus 44%。22/480 链被标记接触 held-out 材料，剔除后中位分变化 ≤0.006、排序不变；GPT-5.6-sol 构建的 30 个环境上 solver 排序同样保持。**失败案例**：部分最终提交低于自己此前保存的更优版本（发现≠保留）；低分模型探索更少、更依赖刷开发集。

## 5. 局限与启发

**论文自述局限**：任务经有限算力改编，超复现基线≠原研究问题上的进展；未隔离"继承记录"与"额外求解时间"的贡献；轨迹未用于训练；部分环境仍可接触评分材料；专家评审仅 90/180、每人一评、无人类一致性估计；行为标签由模型生成无人工验证；未消融构建角色；语料按需发放。

**启发**：(1) 信息隔离的三角色互相制衡，是自动产出可信评估环境的关键；(2) "复现须优于起始解"是廉价有效的验收门槛；(3) 79% 修理率表明自动构建本质是"验证–修理"循环，评估器缺陷（66% 检不出失败）是主要瓶颈；(4) 专家与 agent judge 在饱和/捷径维度系统性分歧，规模化仍需专家审查；(5) 起始解=0、target=1 的归一化便于跨域聚合；(6) "误差棒意识"与"保留最优版本"是可干预的改进目标。
